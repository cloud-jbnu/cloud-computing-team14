# crawler

학교 공지, 공모전·대회, 채용, 테크 트렌드를 수집해 공통 형식([docs/api.md](../docs/api.md)의 Item)으로 저장합니다.
중복을 걸러 낸 새 글만 AI로 요약하고, 웹에 보여 줄 데이터로 저장한 뒤 디스코드 서버 채널에 올립니다.
AWS Lambda에서 EventBridge 스케줄(기본 1시간)로 실행됩니다.

## 흐름

```
collect    수집기마다 목록 페이지를 읽어 글을 모음
find_new   형식 검사 → 중복 제거 → 처음 보는 글만 남김
backlog    처음 수집하는 사이트의 밀린 글을 골라 둠 (저장은 하되 post·notify에서 뺌)
cap        새 글이 30건을 넘으면 최신 글부터 30건만 처리 (나머지는 다음 실행)
summarize  새 글의 본문을 가져와 Gemini로 요약 2~3줄 + 분야 태그
save       DynamoDB에 저장 (웹은 GET /items로 읽음)
post       디스코드 서버 채널에 요약과 함께 게시, 키워드 역할 멘션
notify     키워드 구독자에게 DM
```

요약·게시·알림 중 하나가 실패해도 나머지는 계속합니다. 키나 토큰을 넣지 않은 기능은 꺼진 채로 넘어갑니다.

## 구조

```
crawler/
├─ src/
│  ├─ handler.py        Lambda 진입점 (위 흐름)
│  ├─ dedupe.py         중복 제거
│  ├─ backlog.py        처음 수집하는 사이트의 밀린 글은 알리지 않음
│  ├─ summarize.py      AI 요약 (Gemini)
│  ├─ channels.py       디스코드 서버 채널 게시
│  ├─ notify.py         디스코드 구독 DM
│  ├─ common/           수집기 공용: http(요청), item(id·날짜), board(학교 게시판)
│  └─ sources/          사이트별 수집기 (사이트 하나당 파일 하나)
├─ tests/               네트워크·AWS 없이 도는 테스트, fixtures/ 에 실제 응답 조각
└─ requirements.txt
```

## 수집하는 사이트

| 수집기 | 사이트 | 분류 | id 앞부분 |
|---|---|---|---|
| `univ_jbnu` | 전북대 교내공지 | univ / 전북대 | `jbnu` |
| `univ_cbnu` | 충북대 공지사항 | univ / 충북대 | `cbnu` |
| `univ_knu` | 경북대 공지사항 | univ / 경북대 | `knu` |
| `univ_pnu` | 부산대 공지사항 | univ / 부산대 | `pnu` |
| `jumpit` | 점핏 신입 채용 (전체 쪽) | jobs / 신입·인턴 | `jumpit` |
| `dev_event` | Dev-Event 저장소의 대회 (마감 지난 대회 제외) | contest | `devevent` |
| `geeknews` | GeekNews RSS | tech / 최신기술 | `geeknews` |
| `github_trending` | GitHub Trending | tech / GitHub | `github` |

수집하지 않기로 한 사이트:

- **충남대, 전남대**: `robots.txt`가 모든 경로의 수집을 막고 있습니다 (`Disallow: /`).
- **원티드**: 자동 요청을 403으로 차단합니다.

막아 둔 사이트는 브라우저인 척하는 식으로 우회하지 않습니다. 공식 API나 RSS가 생기면 그때 붙입니다.

## 중복 제거

같은 글이 두 번 저장·요약·알림되지 않게 [`src/dedupe.py`](src/dedupe.py)가 세 번 걸러 냅니다.

| 단계 | 막는 중복 | 방법 |
|---|---|---|
| 실행 내 | 한 번의 수집에서 같은 글이 두 번 나옴 (상단 고정 공지 등) | 같은 `id`는 먼저 나온 것만 남김 |
| 이미 있음 | 이전 실행에서 저장한 글 | `ITEMS_TABLE`에 같은 `id`가 있으면 제외 |
| 사이트 간 | 다른 사이트에 올라온 같은 내용 | 글마다 주소 키와 제목 키를 만들어 `SEEN_TABLE`에 사이트 이름과 함께 적어 두고, 새 글의 키가 다른 사이트 이름으로 이미 있으면 제외 |

- **id가 기준입니다.** 수집기는 사이트의 글 번호로 `id`를 만들어, 같은 글이면 매번 같은 값이 나오게 합니다. 글 번호가 없으면 주소의 해시를 씁니다.
- **주소 키**: `http/https`, `www.`, 끝의 `/`, `#` 뒤, `utm_*` 같은 추적 파라미터를 뗀 주소.
- **제목 키**: 소문자로 바꾸고 앞의 `[공지]` 같은 머리말과 공백·문장부호를 뗀 제목. 8자보다 짧으면 비교하지 않습니다. 채용 공고는 회사 이름을 붙여 비교합니다 (회사만 다른 같은 제목이 많음).
- 제목 키는 **다른 사이트끼리만** 비교합니다. 같은 학교가 매주 같은 제목으로 올리는 공지는 서로 다른 글입니다.
- 키는 60일 뒤 지워져서, 내년의 같은 이름 행사는 새 글로 봅니다.
- 이미 저장한 글은 제목이나 내용이 바뀌어도 덮어쓰지 않습니다.
- 제목이 비슷하지만 똑같지 않은 글은 잡지 않습니다.

실행 결과는 CloudWatch 로그에 `수집 N건 → 형식 오류 …, 실행 내 중복 …, 이미 있음 …, 사이트 간 중복 …, 새 글 …`로 남습니다.

## 처음 수집하는 사이트의 밀린 글

처음 배포하거나 새 사이트를 붙이면 그 사이트 목록에 이미 있던 글(점핏 58건 등)이 한꺼번에 새 글로 잡힙니다. 게시일이 없는 사이트는 몇 주 된 글도 수집한 날짜가 되므로, 그대로 두면 디스코드 채널 게시와 키워드 DM이 쏟아집니다. [`src/backlog.py`](src/backlog.py)가 이를 막습니다.

- 사이트를 처음 본 실행에서 그때 잡힌 새 글의 id를 `SEEN_TABLE`에 `source#사이트` 키로 적어 둡니다 (만료 없음).
- 이 밀린 글은 한 번에 30건 상한 때문에 여러 번에 나눠 저장되더라도 **저장과 요약만 하고 게시·알림은 하지 않습니다.** 웹에는 그대로 보입니다.
- 그 뒤에 올라온 글은 평소처럼 알립니다.
- 밀린 글을 확인하다 DynamoDB 오류가 나면 그 실행은 아무것도 알리지 않습니다. 오래된 글 수십 건을 잘못 알리는 것보다 한 번 덜 알리는 쪽이 낫기 때문입니다.

## AI 요약

[`src/summarize.py`](src/summarize.py)가 새 글의 제목과 본문을 Gemini API에 보내 요약 2~3줄과 분야 태그를 받습니다.

- 새 글이 저장될 때 **한 번만** 요약하고 결과를 글과 함께 저장합니다. 웹과 디스코드는 저장된 요약을 읽기만 합니다.
- 10건씩 묶어 보내므로 한 번 실행에 요청은 최대 3번입니다.
- 본문은 저장하지 않습니다. 요약에만 쓰고 버립니다.
- `GEMINI_API_KEY`가 없거나 호출이 실패하면 요약 없이 저장합니다.
- 제목을 되풀이할 뿐인 요약 줄("경진대회 운영 안내" → "경진대회를 운영함")은 뺍니다. 줄을 두 글자씩 끊어 70% 이상이 제목에 있으면 되풀이로 봅니다. 본문이 이미지나 첨부파일뿐인 공지에서 자주 나오며, 줄이 모두 빠지면 요약 없이 분야 태그만 저장합니다. 모델이 단어를 바꿔 쓴 되풀이("Adobe" → "어도비")는 잡지 못합니다.
- 분야 태그는 글의 핵심 분야만 **최대 2개** 붙입니다. 펌웨어·임베디드·회로·하드웨어처럼 8개 분야에 들어맞지 않는 글과 장학·어학·행사 공지는 태그가 없습니다.
- 요약에 성공한 글은 수집기가 붙인 태그 대신 AI 태그를 씁니다. 점핏의 직무 분류는 회사가 여러 개를 골라 둬서(예: 회로 설계 공고에 "인공지능/머신러닝") 그대로 쓰면 틀린 태그가 많기 때문입니다. 수집기 태그는 본문에 담겨 AI가 참고하고, 요약에 실패한 글에만 남습니다.

## 새 사이트 추가하기

1. 그 사이트의 `robots.txt`와 이용 약관에서 수집을 막지 않는지 확인합니다.
2. `src/sources/`에 파일을 만들고 `fetch()`가 Item 딕셔너리 목록을 돌려주게 합니다. 요청은 `common.http`로만 보냅니다.
   - `id`는 `item.make_id("사이트이름", 글번호)`로 만듭니다. 앞부분은 다른 수집기와 겹치면 안 됩니다.
   - 목록에서 본문까지 얻을 수 있으면 Item에 `"body"`로 넣습니다 (요약에만 쓰고 저장하지 않음).
   - 본문 페이지를 따로 읽어야 하면 `fetch_body(item)`을 만듭니다. 새 글에만 호출됩니다.
   - 분야 태그(`fields`)를 붙인다면 [`src/common/item.py`](src/common/item.py)의 `FIELDS`에 있는 값만 씁니다.
   - 첫 쪽만 읽는다면, 바쁜 날 실행 주기(최대 3시간) 동안 올라오는 글이 첫 쪽에 다 들어가는지 확인합니다. 모자라면 여러 쪽을 읽게 합니다 (`jumpit.py` 참고).
3. 실제 응답에서 필요한 부분만 잘라 `tests/fixtures/`에 넣고 파서 테스트를 씁니다.
4. `handler.py`의 `SOURCES`에 등록합니다.

**학교를 추가할 때**는 위 순서에 더해 학교 이름을 세 곳에 같이 넣습니다: [`src/common/item.py`](src/common/item.py)의 `SCHOOLS`, `web/js/data.js`의 `SUBTYPES.univ`, `api/src/schools.py`의 `SCHOOLS` (웹의 "내 학교" 목록과 챗봇이 씁니다). 수집기 파일의 `SCHOOL`과 이름이 같아야 하며, 어긋나면 `tests/test_constants.py`가 실패합니다. 디스코드 서버에 학교 이름으로 채널도 만듭니다.

분야나 카테고리를 추가·변경할 때는 `src/common/item.py`와 함께 `web/js/data.js`, `api/src/items.py`, `docs/api.md`, 요약 프롬프트(`src/summarize.py`)의 기준도 고칩니다. 하나라도 빠지면 `tests/test_constants.py`가 실패합니다.

## 로컬 실행

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

pytest                      # 테스트 (네트워크 없이 실행)
python src/handler.py       # 실제 사이트에서 수집 → 중복 제거한 결과 출력
python src/handler.py 5     # 최신 5건은 본문을 가져와 요약까지 (.env에 GEMINI_API_KEY 필요)
python src/summarize.py     # 예시 글 2건을 실제로 요약해 출력
python src/channels.py      # 디스코드에 올릴 메시지를 출력만 (--send 를 붙이면 실제 게시)
python src/notify.py        # 구독 DM 메시지를 출력만
```

로컬 실행은 DynamoDB에 저장하지 않고 디스코드에도 올리지 않습니다 (`--send` 제외). AWS 자격 증명이 없어도 됩니다.
DB가 없어서 "이미 있음"은 항상 0이고, 이번에 모은 글끼리만 중복을 비교합니다.

## 디스코드

- **서버 채널 게시**: 채널 이름과 키워드 역할 준비는 [bot/README.md](../bot/README.md) 참고. `DISCORD_BOT_TOKEN`과 `DISCORD_GUILD_ID`가 둘 다 있어야 켜집니다.
- **구독 DM**: 웹에서 등록한 키워드가 글의 `title`·`source`·`subtype`에 들어 있으면 그 사용자에게 DM을 보냅니다. 봇과 같은 서버에 있는 사용자에게만 보낼 수 있습니다.
  - 웹에서 "내 학교"를 정한 사용자(`PROFILES_TABLE`)는 학교 공지 중 **내 학교 글만** 받습니다. "목록에 없는 학교"로 정했으면 학교 공지는 받지 않고, 학교를 정하지 않았으면 예전처럼 모든 학교 공지를 받습니다. 학교 설정을 못 읽으면 예전처럼 보냅니다.
- 둘 다 게시일이 3일(`notify.MAX_AGE_DAYS`)보다 오래된 글은 보내지 않습니다. 처음 배포했을 때 예전 글로 알림이 쏟아지는 걸 막습니다.
